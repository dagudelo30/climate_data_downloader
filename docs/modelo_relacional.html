Modelo relacional

En PostgreSQL (esquema climate): grid y cell (con el polígono de cada celda si hay PostGIS), las tres tablas Gold particionadas por grilla (100 m, 500 m, 1 km, 5 km o las que se pidan), el diccionario variable y el catálogo ingest_manifest. En Parquet/DuckDB son las mismas tablas por grilla, con latitud y longitud en cada fila. Las grillas están alineadas a múltiplos de su resolución, así que las escalas se cruzan por aritmética de índices, sin tablas de cruce.

Las mismas tablas existen en DuckDB (gold/<grilla>/climate.duckdb) con --output-format duckdb. Migraciones versionadas en src/climate_pipeline/storage/migrations/.

Cómo se cruzan las escalas

Con una grilla fina de ancho W₁₀₀ (por ejemplo 100 m) y una gruesa de factor k (5 para 500 m, 10 para 1 km, 50 para 5 km), desplazamiento (r₀, c₀) entre sus esquinas y ancho W_k:

fila = cell_id_100 // W₁₀₀ ; col = cell_id_100 % W₁₀₀
cell_id_k = ((fila − r₀) // k) × W_k + (col − c₀) // k

La función parent_cell_ids(fine, coarse, cell_ids) de climate_pipeline.domain.grid lo calcula. Cada grilla se calcula desde los datos nativos a su propia resolución; con --nested, además, el valor de una celda gruesa es exactamente el promedio de sus celdas finas.

-- PostgreSQL: semanas de 2026 en 1 km con covariables estáticas y polígono de la celda
SELECT c.geom, w.*, s.static_elevation_m, s.urban_buildings_frac
FROM climate.gold_epiweekly w
JOIN climate.cell c USING (grid_name, cell_id)
JOIN climate.static_covariates s USING (grid_name, cell_id)
WHERE w.grid_name = '1km' AND w.epi_year = 2026;

-- DuckDB sobre Parquet: lo mismo desde el lago local
SELECT w.*, s.* EXCLUDE (cell_id, latitude, longitude)
FROM read_parquet('data/gold/1km/parquet/epiweekly/**/*.parquet') w
JOIN read_parquet('data/gold/1km/parquet/static/covariates.parquet') s USING (cell_id)
WHERE w.epi_year = 2026;
